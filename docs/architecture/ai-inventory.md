## Source responsibilities and authority

| Source | Responsibility and boundary |
| --- | --- |
| **Azazel-MIO** | Shared advisory reasoning over caller-provided observations and typed projections. Hypotheses, unknowns, suggested checks, and Knowledge-derived displays remain unverified advisory data; MIO does not own product decisions, authorization, enforcement, or automatic model promotion. The shared API and offline-learning facilities described below are candidate evidence from PR #15, not the public `main` baseline. ([PR #15](https://github.com/01rabbit/Azazel-MIO/pull/15)) |
| **Azazel-Edge** | Owns its deterministic evaluation and applied-control authority. The MIO comparison/model lanes in the current public PR chain are explicitly optional/advisory and do not replace Edge scoring, actions, or enforcement. The public MIO evidence in scope does not establish a live authenticated producer, full-node interoperability, or an approved Knowledge contract. ([MIO #15](https://github.com/01rabbit/Azazel-MIO/pull/15), [MIO #18](https://github.com/01rabbit/Azazel-MIO/pull/18)) |

([Fabric #73](https://github.com/01rabbit/Azazel-Fabric/pull/73), [Fabric design principles](https://github.com/01rabbit/Azazel-Fabric/blob/main/docs/design-principles.md)) |

An MIO explanation, model hypothesis, suggested check, or Knowledge reference is advisory data, never an authorization or action. |
| **Azazel-Deception** | Owns approved decoy execution, isolation, exposure controls, observation collection, and deterministic termination/reset; MIO does not operate decoys. ([Azazel system architecture](https://github.com/01rabbit/Azazel)) |

## MIO candidate API boundary

MIO PR #15 proposes `AssistantCore.explain` over a validated frame and optional typed Knowledge projections. The optional model callable is injected by a caller; the candidate common package does not launch a model process or make network requests. Its `Assistance` result can carry observations, unverified hypotheses, unknowns, suggested checks, Knowledge projections, handoff data, and a bounded reasoning trace. The API/runtime source reviewed at that snapshot also adds ticket-scoped lifecycle cancellation, suppresses stale/non-current frame-derived output, and closes failed cycles so retries can proceed. Product UI and operational audit persistence remain outside that common API. ([PR #15](https://github.com/01rabbit/Azazel-MIO/pull/15), [API/runtime source reviewed at snapshot](https://github.com/01rabbit/Azazel-MIO/tree/ba65b0107fb834775bf7878bc2a400cb28acbf36))

The candidate capability broker and bounded reasoning loop are in-process, allowlisted, read-only, and bounded. Offline replay/ranking/learning work is evaluation-only; it does not establish a verified practice corpus, a production learned artifact, actual training on operational outcomes, or automatic admission/promotion. No model promotion or actual K-training claim is made here. ([PR #15](https://github.com/01rabbit/Azazel-MIO/pull/15))
